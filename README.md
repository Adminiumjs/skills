# Adminium agent skills

Agent Skills for building on [Adminium](https://adminium.dev) — an open-source engine that
introspects a database and generates an admin dashboard for it.

A skill is plain markdown plus a couple of scripts. It teaches a coding agent the conventions,
constraints and failure modes of a codebase, so you get a page that matches the repo instead of
a page that merely compiles.

## Install

```bash
npx skills add Adminiumjs/skills
```

Works with Claude Code, Cursor, Codex, OpenCode and the other agents [`npx skills`](https://github.com/vercel-labs/skills)
supports. To install into a specific agent, pass `-a`; to see what is in here without installing,
pass `--list`.

## What is in here

### `adminium-customer-page`

Adds one customer-facing or staff-facing page to an Adminium micro-SaaS app and wires it to the
scoped public API, rather than to the demo data the app ships with.

An Adminium app has up to three sides. The **dashboard** is generated by Adminium from your
database and is never hand-built. The **staff** and **customer** sides live in the app repo —
this is the skill for those.

**Its first action is to refuse.** Before writing anything it compiles the repo's `manifest.json`
offline and prints the tables, columns and row types a page may actually use. If the manifest does
not validate, it stops and says so. Fixing the manifest becomes the task; the page is not. Every
line written past an unvalidated manifest is a guess about a schema nobody has seen.

It also says plainly what the public API cannot do — no money, no uploads, no live updates, no
deletes, nothing outside the scope you granted — instead of routing around it.

**Requires Adminium 0.2.3 or later.** Check with `adminium --version`.

## The scope is the authorization

The public API is off by default. When you turn it on, you write a scope document that names
exactly which tables and columns are readable, and a publishable key reaches that and nothing
else. The key is not a login: it carries no role and cannot read through the rest of the API.

That is the whole security model, and it belongs to the operator of the database — not to the
app, and not to this skill. If a page needs a column the scope does not expose, the scope has to
change first, in **Studio → Public API**. The skill is written to ask rather than to work around
it.

## Contributing

The canonical source lives in the Adminium monorepo and is mirrored here. Please open an issue at
[Adminiumjs/skills](https://github.com/Adminiumjs/skills/issues) describing what the skill got
wrong on your repo — a skill that is confidently wrong about a convention is worse than no skill,
so concrete counter-examples are the most useful thing you can send.
